# Public project hub: continuity contract

1. Keep this as the only new public showcase; existing historical repositories stay private.
2. Every latest tested version should have a tagged GitHub Release with verification, version, SHA-256 and known limitations. Use project prefixes aurora-ai-v, horizon-boost-v and thalvoryn-v.
3. Development/test builds must be marked prerelease. Do not misrepresent unit tests as end-to-end game or AI integration tests.
4. Keep the site in docs/ synchronized with latest project versions and release metadata.
5. No private chat exports, AI memory, auth credentials, local user paths, temporary build logs, tool histories or cached packages in public Git.
6. Aurora: keep source clean of node_modules, dist binaries, old audit duplicates, screenshots with personal data. Keep original folder unchanged.
7. Vanta FX: do not bundle Magpie executables or hook/inject game DLLs. Capture FPS, output FPS and game FPS must remain distinct.
8. Thalvoryn: public binary release only after source/asset licensing is verified; keep credits and variants.
9. Back up before editing and keep rollback instructions in the private external archive.
10. Never overwrite released tag assets silently. Publish a new version and preserve old verified releases.
